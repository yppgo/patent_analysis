# 假设创新性增强方案 — 评审与讨论

---

## Claude 评审意见

### 总体评价：方向有价值，但方案存在结构性问题

方案工程上很完整，但存在几个与**已有实验发现相矛盾**的设计决策，如果直接实施，可能重蹈 A 模式的覆辙。

### 一、核心问题：与已有实验发现冲突

我们最重要的实验发现是 **A < D（知识图谱约束反而降低质量）**。原因是刚性结构约束限制了 LLM 的生成自由度。

而方案的核心设计是：

> **"禁止输出未绑定 seed 的假设"** (原方案第3.2节)

这本质上和 A 模式犯了同一个错误——用固定代码产出的模板去**强约束** LLM 输出。区别只是从"知识图谱路径"换成了"异常种子"，约束逻辑是一样的。

**风险**：如果种子质量不高或覆盖面不够，E 方案可能表现不如 C，甚至不如 B。

### 二、具体问题逐条分析

#### 1. 异常种子检测器（原方案第2节）— 部分可行，部分不适用

| 检测器 | 评估 |
|--------|------|
| `subgroup_reversal` | **不确定** — 需要分类变量做子群划分，专利数据中能否找到合适的分组变量待验证 |
| `tail_anomaly` | **可行** — Top/Bottom 分位比较是通用手段 |
| `structural_bridge` | **可行** — 直接利用现有 GraphPreview 的拓扑信息 |
| `temporal_break` | **不确定** — 需要时间序列粒度足够，专利年度数据可能窗口太粗 |

4 个检测器中只有 1-2 个能稳定产出有意义的种子，种子数量可能不足以支撑"必须绑定 seed"的硬约束。

#### 2. 评分函数 `N × T × U × G`（原方案第4节）— 设计有缺陷

- **乘法公式太脆弱**：任何一项为 0，总分直接归零。应改为加权求和。
- **N (Novelty)**："与历史/文献相似度低"——没有文献语料库，怎么算？这一项在实际实现中会退化为随机打分或手动判断。
- **U (Untriviality)**："常识黑名单"——谁来维护？这是人工策展，不可复现，论文审稿人会质疑。
- **G (Gain)** 定义为"是否解释反常现象"——这其实就是 seed 命中率的变形，与 N 的设计意图重叠。

#### 3. 可检验性网关（原方案第5节）— 有价值但位置错误

网关本身是好想法（变量映射检查、样本量检查），但：
- 系统的 CodingAgent 已经有 **15轮重试机制**，本质上就是一个隐式的"可执行性网关"
- 如果在 Strategist 阶段就做硬过滤，会丢失一些"看起来不可执行但 CodingAgent 能创造性解决"的假设

#### 4. 评估指标（原方案第6.2节）— 自引用问题

- **"Seed 命中率"** 是自引用指标——强制要求绑定 seed，然后测量绑定率，这永远是 100%
- **"机制多样性"**（mediation/moderation/interaction/stage）是好指标，但不需要种子系统就能衡量

#### 5. 工程量（原方案第7-8节）— 对硕士论文偏重

3 个全新模块 + strategist 大改 + 新实验模式 + 新评估指标，10天偏乐观。关键问题：

> 这些工程量换来的论文贡献是什么？

答案是"一个新的 E 方案数据点"。但我们已经有 D→A→B→C 的完整消融链，论文故事线是自洽的。E 方案如果表现好，锦上添花；如果表现不好（有此风险），反而需要额外解释。

### 三、哪些想法值得保留

| 想法 | 建议 |
|------|------|
| 异常检测作为**额外输入** | 保留，但作为数据洞察的补充，**不做强绑定** |
| 假设质量评估 | 保留，但用于**事后评估**（论文分析用），不做生成阶段过滤 |
| 可检验性检查 | 轻量化保留，做**软警告**而非硬拦截 |
| 机制多样性指标 | 保留，加入评估脚本 |

### 四、替代建议

如果目标是提升假设创新性，更符合已有实验发现的做法是：

**方案 A：轻量增强（推荐，3-4天）**
1. 在 DataInsight 阶段增加异常检测（tail_anomaly + structural_bridge），产出作为数据洞察的一部分注入 prompt
2. 在 prompt 中用**软引导**（"优先解释数据中的反常模式"）而非硬约束
3. 事后用假设质量评分做论文分析

**方案 B：按原方案做（10天+）**
- 风险较高，工程量大，可能重蹈 A < D 的覆辙

### 五、关键背景信息

供参考的已有实验结果（LLM-as-Judge 评分，满分25）：

| 方案 | 评分 | 说明 |
|------|------|------|
| D_baseline0 | 19.67 | 纯 LLM，无图谱无数据洞察 |
| A_template | 14.33 | 加入知识图谱模板约束 |
| B_data_aware | 21.67 | 加入数据预览+数据洞察 |
| C_iterative | 24.00 | B + 两轮迭代 |

核心发现：**A < D 说明刚性结构约束会降低 LLM 生成质量**，任何新增约束机制都需要警惕这一点。

## Claude 二轮评审：对 GPT 回复的回应

### 对 E-lite 部分：完全同意

第一部分的 E-lite 方案（软引导 + 软网关 + 事后评估）和我的建议几乎完全一致，没有分歧。

### 对 E-hybrid 反驳的逐条回应

#### 反驳1："至少 40% 假设有 seed_ref" — 不同意

这个约束换了个说法但本质没变。问题在于：

- LLM 收到 prompt 里的异常信号后，它**自然就会引用**这些信号来构建假设——不需要设 40% 的配额
- 如果异常信号质量好，LLM 自发引用率可能超过 40%；如果信号质量差，强制凑 40% 反而拉低整体质量
- 设了配额就需要在代码中做计数和重试逻辑，又增加了工程复杂度

**结论**：40% 配额是一个不必要的中间态。好的异常信号自然会被引用，差的信号不该被强制引用。

#### 反驳2："两级网关，Level-1 硬拦截" — 不同意

GPT 给的 Level-1 硬拦截条件是：关键列不存在、样本量过低、输出契约缺失。

回到系统的实际情况：

- **关键列不存在** → CodingAgent 在执行时会立刻报错，15轮重试中可以自动修正。硬拦截省的只是一次 CodingAgent 调用的成本。
- **样本量过低** → 什么算"过低"？阈值怎么定？专利数据的不同切面样本量差异巨大，硬编码阈值很可能误杀有价值的假设。
- **输出契约缺失** → Methodologist 本身就会补全输出格式，这是它的既有职责。

**结论**：Level-1 的三个条件要么已被现有机制覆盖，要么难以可靠实现。实际收益不大，但增加了一个新模块的维护成本。

#### 评分函数 `Score = Gate(T) * (wN*N + wU*U + wG*G)` — 不可落地

比原来的乘法好，但核心问题没解决：
- **N 怎么算**？还是没有文献语料库，实现时会退化为随机打分
- **U 怎么算**？还是依赖人工黑名单，不可复现
- **wN, wU, wG 怎么调**？3个权重 × 3个问题的实验规模根本调不出来

这个评分函数在论文里写公式好看，但实际实现时会退化为 LLM 打分或人工赋值，那不如直接用现有的 LLM-as-Judge 做事后评估。

### 最终判断

| 方案 | 态度 | 理由 |
|------|------|------|
| E-lite（GPT 第一版） | **同意** | 与已有实验发现一致，工程量可控，论文叙事自洽 |
| E-hybrid（GPT 反驳版） | **不同意** | 40%配额是伪中间态，两级网关被现有机制覆盖，评分函数不可落地 |

**建议不变**：做 E-lite，4天内完成。软引导注入异常信号 + 事后评估新增指标。不需要 hybrid 方案增加复杂度和风险。
