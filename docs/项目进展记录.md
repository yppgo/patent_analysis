## 一、项目概述

### 1.1 研究背景

本项目构建了一套**多智能体专利分析系统**，采用四 Agent 流水线架构，配合双知识图谱，实现从用户研究问题到自动化数据分析的端到端流程。

### 1.2 论文核心创新点

**"数据感知的分析方案生成"方法**：解决现有系统中 Strategist 从未看过真实数据就开始规划、方案与具体数据脱节的问题。

两项改进：
1. **数据洞察生成**：在方案设计前，让 LLM 基于真实数据的统计特征、图结构特征、领域摘要样本生成可检验的研究洞察
2. **两轮迭代机制**：第一轮探索性分析的结果反馈给 Strategist，驱动第二轮更深入的分析

## 二、系统架构

### 2.1 四 Agent 流水线

```
用户研究问题
     │
     ▼
┌─────────────┐   因果图谱 + 方法图谱
│  Strategist  │◄──────────────────────
│  (策略师)     │   DataPreview + GraphPreview + 数据洞察
└──────┬──────┘
       │ DAG 蓝图（任务有向无环图）
       ▼
┌─────────────┐
│ Methodologist│   方法图谱查询
│  (方法学家)   │   为每个任务生成详细分析规范
└──────┬──────┘
       │ 任务规范（JSON）
       ▼
┌─────────────┐
│ CodingAgent  │   生成 + 执行 Python 代码
│  (编程代理)   │   自动纠错（最多 5 轮迭代）
└──────┬──────┘
       │ 执行结果
       ▼
┌─────────────┐
│  Reviewer    │   评估分析质量
│  (审阅者)     │   给出改进建议
└─────────────┘
```

### 2.2 双知识图谱

| 图谱 | 文件 | 规模 | 用途 |
|------|------|------|------|
| 因果图谱 | `src/graphs/causal_graph_query.py` | 30 个变量，99 条因果路径，6 种模板策略 | 提供领域因果假设 |
| 方法图谱 | `src/graphs/method_graph_query.py` | 86+ 种分析方法 | 为任务匹配具体分析方法 |

### 2.3 LLM 配置

| 角色 | 模型 | 用途 |
|------|------|------|
| Strategist / Methodologist | DashScope qwen3-max | 方案设计、方法匹配 |
| CodingAgent | Claude (Anthropic) | 代码生成与执行 |
| 数据洞察生成 | DashScope qwen3-max | 解读数据特征 |

## 三、本轮改进内容（已完成）

### 3.1 Phase 1：增强 DataPreview

**文件**：`src/utils/data_preview.py`（602 行）

新增功能：
- `_compute_cross_column_stats()`：计算数值列间 Pearson 相关系数、低基数分类列的分组对比、日期列的时间趋势
- `_sample_abstracts_stratified()`：按 IPC 部分层抽样 20-30 条摘要（每条截断 300 字符，固定 random_state）
- `get_abstracts_prompt_string()`：独立的摘要 Prompt 输出，避免所有 Prompt 都带上冗长摘要
- `generate()` 新增 `cross_column_stats` 和 `sampled_abstracts` 字段
- `to_prompt_string()` 末尾追加跨列统计段落

### 3.2 Phase 1.5：新建 GraphPreview 模块

**文件**：`src/utils/graph_preview.py`（451 行，新建）

设计原则：图的构建和标准算法是通用的（不依赖领域），图结构的解读交给 LLM。

核心功能：
- **自动图构建**：扫描 DataFrame，根据列特征自动构建图
  - 分隔符列 + 人名元素 → 合作图
  - 分隔符列 + 分类码元素 → 共现图
  - 分隔符列 + 专利编号元素 → 引用图
- **标准图算法**：
  - Louvain 社区检测（含社区代表节点提取）
  - 介数中心性（大图用 k=500 近似采样）
  - 连通分量统计
  - 度分布统计
- **大图保护**：节点 >10K 时跳过 O(n^2) 算法，只算度分布
- **输出**：结构化文本，只含数字和节点名，不做语义解读

实测构建了 6 个图（发明人合作网络、IPC 共现网络、引用网络等），总耗时约 15-20 秒。

新增依赖：`networkx>=3.0`、`python-louvain>=0.16`

### 3.3 Phase 2：数据洞察生成

**文件**：`src/agents/strategist.py`（1513 行）

新增方法：
- `_generate_data_insights()`：调用 LLM，基于三份输入（DataPreview + GraphPreview + 摘要样本）生成 5-8 条洞察
  - 洞察分三类：统计信号型、图结构型、内容驱动型
  - 每条洞察包含：观察、假设、涉及列名、建议分析方法、非常识性理由
- `_format_data_insights_for_prompt()`：格式化洞察为 Prompt 注入文本

Prompt 层次结构（第一轮）：
```
用户目标
  → 数据驱动的研究洞察（主驱动）
  → 因果图谱参考（辅助）
  → 数据可用列名及语义
  → 数据预览（含跨列统计）
  → 图结构预览
  → 约束和输出格式
```

### 3.4 Phase 3：两轮迭代机制

**文件**：`src/agents/strategist.py`

`process()` 方法新增参数：
- `round`：轮次（1 或 2）
- `previous_results`：第一轮的执行结果摘要
- `disable_data_insights`：是否禁用数据洞察（用于基线实验）

新增方法：
- `_generate_refined_blueprint()`：第二轮专用，接收第一轮结果，进行差距分析，生成更深入的分析方案

迭代流程：
```
第一轮（探索性）：增强 DataPreview → GraphPreview → 数据洞察 → DAG 蓝图
                                ↓ 执行 ↓
第二轮（验证性）：第一轮结果 + 差距分析 → 更深入的 DAG 蓝图
```

### 4.5 核心发现与论文解读

#### 发现 1：整体性能梯度 A < D < B < C

```
A_template (14.33) < D_baseline0 (19.67) < B_data_aware (21.67) < C_iterative (24.00)
```

C 方案（完整系统）相比 D 方案（纯 LLM 基线），总分提升 **22%**（19.67 → 24.00）。在各维度上：
- 针对性提升 25%（4.00 → 5.00）
- 创新性提升 56%（3.00 → 4.67）
- 分析深度提升 25%（4.00 → 5.00）

**论文表述建议**：
> 实验结果表明，本文提出的数据感知分析方案生成方法（C 方案）在所有评估维度上均显著优于纯 LLM 基线（D 方案），总分提升 22%，其中创新性维度提升最为显著（56%），验证了"数据洞察 + 迭代优化"机制的有效性。

#### 发现 2：知识图谱单独使用的"约束悖论"（A < D）

这是实验中最具讨论价值的发现：A_template（使用知识图谱）的评分反而**低于** D_baseline0（纯 LLM）。

| 维度 | D (纯LLM) | A (+知识图谱) | 差异 |
|------|:---------:|:------------:|:----:|
| 相关性 | 4.33 | 3.33 | -1.00 |
| 针对性 | 4.00 | 3.00 | -1.00 |
| 创新性 | 3.00 | 2.33 | -0.67 |
| 深度 | 4.00 | 2.67 | -1.33 |
| **总分** | **19.67** | **14.33** | **-5.34** |

**原因分析**：
1. 因果图谱的 6 种模板策略将 LLM 的思维锁定在预设的因果路径中，限制了自由探索
2. 方法图谱在没有数据特征引导时，匹配到的方法可能过于通用
3. 纯 LLM（D）反而能根据列名灵活设计方案，不受预设框架约束

**论文表述建议**：
> 值得注意的是，仅使用知识图谱模板（A 方案）的表现反而低于纯 LLM 基线（D 方案），这揭示了一个"约束悖论"：结构化知识在缺乏具体数据上下文时可能过度约束 LLM 的方案生成能力。这一发现进一步印证了本文数据感知方法的必要性——知识图谱需要与数据洞察协同工作，才能发挥正向作用。

#### 发现 3：数据洞察的增量价值（D < B）

数据洞察机制使系统超越纯 LLM 能力：

| 自动化指标 | D (纯LLM) | B (+数据洞察) | 提升 |
|-----------|:---------:|:------------:|:----:|
| 针对性引用数 | 2.67 | 7.67 | **+187%** |
| 参数丰富度 | 8.33 | 6.67 | -20% |
| 数据洞察数量 | 0 | 3.00 | +3 条 |
| LLM 总分 | 19.67 | 21.67 | **+10%** |

数据洞察带来的关键改变：
- 方案引用具体数据特征（如 H04L9/40 度=904、质押专利被引均值 3.61）
- 假设从通用常识升级为数据驱动的可检验命题
- 分析方法从标准模板升级为数据定制化配置

**论文表述建议**：
> B 方案通过数据洞察生成机制，将方案的针对性引用数从 2.67 提升至 7.67（+187%），LLM 评分提升 10%（19.67 → 21.67）。数据洞察使 LLM 能够基于数据集的实际统计特征（如相关系数、分组对比）和图结构特征（如社区划分、桥梁节点）设计分析方案，而非依赖通用模板。

#### 发现 4：迭代机制的深度提升（B < C）

两轮迭代带来的系统性提升：

| 自动化指标 | B (单轮) | C (两轮迭代) | 提升 |
|-----------|:--------:|:-----------:|:----:|
| 数据列覆盖率 | 0.26 | 0.42 | **+62%** |
| 方法多样性 | 2.67 | 5.67 | **+113%** |
| 针对性引用数 | 7.67 | 15.33 | **+100%** |
| 参数丰富度 | 6.67 | 12.33 | **+85%** |
| 任务描述详细度 | 48.6 字 | 99.8 字 | **+105%** |
| 生成任务总数 | 2.67 | 5.00 | **+87%** |
| LLM 总分 | 21.67 | 24.00 | **+11%** |

C 方案第二轮的典型新增：
- Q1：负二项回归、BERT 主题建模、发明人网络中介分析
- Q2：层次线性模型+固定效应、LDA 主题建模 (K=8)
- Q3：TF-IDF+IPC 嵌入 KMeans、ANCOVA 协方差分析

**论文表述建议**：
> 两轮迭代机制使方法多样性翻倍（+113%），数据列覆盖率提升 62%，表明第二轮分析有效弥补了第一轮的分析盲区。第一轮以探索性分析为主（验证效应是否存在），第二轮则系统性地引入更高级的分析方法（如中介分析、主题建模），将分析层次从相关性验证提升至因果推断和机制解释。

#### 发现 5：各维度的提升模式

| 维度 | D→A | D→B | D→C | 最大增幅路径 |
|------|:---:|:---:|:---:|:----------:|
| 相关性 | -1.00 | +0.34 | +0.34 | D→B/C |
| 针对性 | -1.00 | +0.33 | **+1.00** | D→C |
| 方法合理性 | -1.33 | 0.00 | +0.34 | D→C |
| 创新性 | -0.67 | **+1.33** | **+1.67** | D→C |
| 深度 | -1.33 | 0.00 | **+1.00** | D→C |

- **创新性**受益最大（+1.67），表明数据洞察帮助 LLM 发现非显而易见的分析角度
- **针对性**稳步提升（+1.00），表明数据感知+迭代使方案越来越贴合具体数据集
- **深度**在迭代后大幅提升（+1.00），第二轮分析从效应验证升级到机制探索

### 4.6 LLM 评估的优劣势分析摘要

以下为 LLM-as-Judge 对各方案的典型评价（可直接用于论文案例分析）：

#### D_baseline0（纯 LLM）典型评价
- **优势**："方法论严谨性，系统控制专利年龄以消除时间累积偏差，采用分层回归+中介分析的组合策略"
- **劣势**："未深入探讨特定技术子领域的调节作用，创新性有限，属于增强版常规分析"

#### A_template（+知识图谱）典型评价
- **优势**："围绕反直觉假设展开，任务简洁高效"
- **劣势**："方法较为单一，仅使用线性回归；缺乏对非线性关系的探索；整体分析框架较扁平，因果推断能力有限"

#### B_data_aware（+数据洞察）典型评价
- **优势**："精准锚定核心密码协议子领域（H04L9/40），采用 Jaccard 多样性指数替代香农熵更适用于稀疏 IPC 分布；使用社区检测识别跨部类融合模式"
- **劣势**："任务数量较少，未覆盖时间趋势维度；回归模型未控制专利年龄"

#### C_iterative（+两轮迭代）典型评价
- **优势**："两轮迭代显著提升分析深度；引入 BERT 主题建模、合作网络度中心性等跨学科方法，实现三角验证；因果推断层次高，是唯一同时兼顾宏观趋势、微观机制与商业价值的方案"
- **劣势**："整体执行复杂度高；部分任务描述模糊"

## 六、评估方法论

### 6.1 自动化指标（10 项）

| 指标 | 计算方式 | JSON 提取路径 |
|------|---------|--------------|
| 数据列覆盖率 | 使用的唯一列数 / 22 | `task_graph[*].implementation_config.columns_to_load` |
| 方法多样性 | 唯一 `task_type` 数 | `task_graph[*].task_type` |
| 任务描述详细度 | `description` 平均字符数 | `task_graph[*].description` |
| 针对性引用数 | 正则匹配具体数据引用次数 | description + question + expected_outcomes |
| 控制变量数 | parameters 中控制变量列表长度 | `parameters.control_vars` |
| 参数丰富度 | parameters 中非空键值对总数 | `implementation_config.parameters` |
| 预期结论具体度 | expected_outcomes 含数值条目比例 | `expected_outcomes` |
| 数据洞察数量 | 仅在 has_insights=True 时计入 | `thinking_trace.selected_insights` |
| 任务总数 | 所有轮次任务数之和 | `rounds[*].total_tasks` |
| 执行成功率 | success_count / total_tasks | `rounds[*].{success_count, total_tasks}` |

### 6.2 LLM-as-Judge 对比评估

- **模型**：qwen3-max，temperature=0.1（保证打分稳定性）
- **方法**：将同一问题的 4 个方案匿名化为 W/X/Y/Z，同时呈现给 LLM 横向对比
- **评分维度**：5 个维度各 1-5 分，总分 25 分
- **去偏设计**：
  - 匿名化标签（LLM 不知道哪个是 A/B/C/D）
  - 强制差异化（每个维度最高分和最低分至少差 1 分）
  - 先分析后打分（要求先输出各方案优劣势，再给出评分）

### 8.1 LLM 驱动的自动化数据分析

近年来，LLM 驱动的数据科学 Agent 成为热门方向。代表性工作包括：

| 系统 | 来源 | 核心方法 | 局限 |
|------|------|---------|------|
| DS-Agent | ICML 2024 | 案例推理(CBR)，从 Kaggle 历史方案库检索相似案例指导 LLM 生成代码 | 关注 ML 建模任务（分类/回归），不生成研究分析方案；用历史案例而非当前数据特征驱动规划 |
| Data Interpreter | ACL 2025 Findings | 动态规划 + 代码执行 + 反馈迭代，优化 LLM Agent 的数据科学工作流 | 聚焦代码执行质量优化，不生成研究假设或分析蓝图；无领域知识图谱支持 |
| Data-to-Dashboard | arXiv 2025 | 多 Agent 企业分析框架，领域检测 + 概念提取 + 多视角分析生成 | 面向可视化仪表板生成，不做统计假设检验或因果分析 |
| AutoML-Agent | arXiv 2024 | 多 Agent 全流程 AutoML，模型选择与超参调优 | 关注下游模型优化，不涉及上游分析方案设计 |

**现有工作的共同空白**：现有数据科学 Agent 要么关注"怎么建模"（DS-Agent），要么关注"怎么执行代码"（Data Interpreter），**忽视了"设计什么分析方案"这一上游关键环节**。在给定研究问题和数据集后，该分析哪些变量、采用什么统计方法、控制哪些混杂因素——这些决策目前仍完全依赖人工。

**参考文献**：
- Guo, S. et al. "DS-Agent: Automated Data Science by Empowering Large Language Models with Case-Based Reasoning." ICML 2024. https://arxiv.org/abs/2402.17453
- Hong, S. et al. "Data Interpreter: An LLM Agent For Data Science." ACL 2025 Findings. https://aclanthology.org/2025.findings-acl.1016.pdf
- "Data-to-Dashboard: Multi-Agent LLM Framework for Insightful Visualization in Enterprise Analytics." arXiv 2025. https://arxiv.org/html/2505.23695v1

### 8.2 LLM 在专利分析中的应用

LLM 与专利分析的结合正在快速发展，但现有工作主要集中在专利文本处理层面：

| 系统 | 来源 | 核心方法 | 局限 |
|------|------|---------|------|
| EvoPat | arXiv 2024.12 | 多 LLM 专利 Agent，RAG + 子任务分解，实现专利摘要/对比/技术评估 | 处理专利文本（摘要、权利要求），不做专利数据集的定量统计分析 |
| KLIPA | arXiv 2025 | 知识图谱 + LLM 的专利问答框架，结合结构化和非结构化检索 | 用 KG 做信息检索和问答，不做数据驱动的分析方案设计 |
| 专利 KG 构建 | Springer 2025 | 从专利数据构建知识图谱，识别专利间隐含关系 | 关注图谱构建本身，不做下游分析 |

此外，2025 年 Springer 发表的专利领域 NLP 综述明确指出："LLM 在专利领域的应用仍不充分（remains underdeveloped and not yet highly prominent）"。

**现有工作的共同空白**：专利 + LLM 的工作全部聚焦于**专利文本处理**（摘要生成、分类、检索），而**专利结构化数据集的定量分析**（专利计量学，patent bibliometrics）—— 如技术影响力驱动因素分析、技术融合趋势识别、国家竞争态势评估 —— 尚无多 Agent 系统支持。

**参考文献**：

### 8.3 知识图谱增强 LLM

知识图谱与 LLM 的结合是当前热点，代表性工作包括：

| 工作 | 来源 | 方法 | 局限 |
|------|------|------|------|
| GraphRAG | Microsoft 2024 | 从文本构建社区图谱，通过社区检测增强 RAG 对全局问题的回答能力 | 用于文本问答，不用于分析方案的因果引导 |
| KG-CoI | 2024-2025 | 利用结构化知识源引导假设生成，减少事实错误 | 最接近本文工作，但用于生物医学假设发现，不是数据分析方案设计 |
| OntoRAG | 2025 | 数据驱动的本体构建，通过聚类和泛化从原始文本抽象概念 | 关注图谱构建过程，不涉及下游分析任务设计 |

**现有工作的共同空白**：现有 KG+LLM 工作中的知识图谱多为从文本抽取的实体关系图，用于增强检索或问答。**将领域因果模型（如"技术多样性→技术影响力"的因果路径）编码为知识图谱，并用于引导统计分析方案设计**的工作尚未出现。

**参考文献**：
- Edge, D. et al. "From Local to Global: A Graph RAG Approach to Query-Focused Summarization." Microsoft Research, 2024.
- "A Survey on Hypothesis Generation Using LLMs." OpenReview, 2024-2025. https://openreview.net/pdf/cd5db9234ab62192f5912ed6843e71d0083ba06e.pdf

### 8.4 LLM 自动化科学发现

更广泛的 LLM 科学发现方向也与本文相关：

| 系统 | 来源 | 方法 | 局限 |
|------|------|------|------|
| AI Scientist v2 | Sakana AI 2025 | 全自动科研 Agent，从假设生成到实验执行到论文撰写 | 面向 ML/CS 计算实验，"数据"是模型训练结果，不处理真实世界结构化数据集 |
| Agent Laboratory | 2025 | 多 Agent 模拟科研实验室 | 同上，不处理外部数据集的统计分析 |

EMNLP 2025 的 LLM 科学发现综述定义了三个自主水平：Level 1（LLM as Tool）、Level 2（LLM as Analyst）、Level 3（LLM as Scientist）。本文系统对应 **Level 2**，但增加了数据感知和领域知识图谱这两个在现有 Level 2 系统中缺失的组件。

### 8.5 本文的独特定位

综合以上四个方向的调研，本文工作的独特性体现在以下三个方面：

#### （1）填补"分析方案生成"的空白

现有数据科学 Agent 关注下游执行（代码生成、模型训练），**忽视了上游的分析方案设计**。本文提出的 Strategist Agent 是首个通过数据特征驱动来自动生成包含变量选择、统计方法、控制变量、子群定义的完整分析方案（DAG 蓝图）的系统。

与最接近的 DS-Agent 的关键区别：
- DS-Agent 从 Kaggle **历史案例**推理 → 本文从**当前数据特征**推理
- DS-Agent 生成 ML 训练代码 → 本文生成**研究分析蓝图**（假设、方法、变量）
- DS-Agent 无领域知识 → 本文融合**领域因果图谱**

#### （2）首次在专利计量学场景应用多 Agent 分析系统

专利 + LLM 的工作全部聚焦文本处理，多 Agent 数据科学的工作全部聚焦 ML 建模。**在专利结构化数据集上做统计分析和假设检验的多 Agent 系统**，本文是首个。

#### （3）实验发现"知识图谱约束悖论"

实验中 A_template（+知识图谱）的评分反而低于 D_baseline0（纯 LLM），即 **A < D**。这一发现在现有文献中未被报告——大多数 KG+LLM 工作都证明"加 KG 效果更好"。本文实验揭示了一个重要前提条件：**知识图谱需要与数据感知机制协同工作才能发挥正向作用**（B > D > A），单独使用反而会过度约束 LLM 的方案生成能力。

## 九、论文可直接使用的结论

### 9.1 主要贡献

1. 提出了**数据感知的分析方案生成方法**，通过 DataPreview（跨列统计）、GraphPreview（图结构分析）和 LLM 洞察生成三层输入，使分析方案能够根据具体数据集的特征自动定制

2. 设计了**两轮迭代优化机制**，第一轮探索性分析的结果反馈驱动第二轮更深入的验证性分析，实现从效应发现到机制解释的层次提升

3. 通过 4 方案 × 3 问题的消融实验，验证了各组件的增量贡献，完整系统相比纯 LLM 基线在 LLM-as-Judge 评分上提升 22%
