# 第五章 实验与评估

## 5.1 实验设计
本章目标是验证三个问题：其一，数据感知模块是否显著提升方案针对性；其二，双知识图谱在不同条件下是否稳定增益；其三，两轮迭代是否提升分析深度与结论质量。为保证结论可归因，实验采用渐进式消融协议，保持数据集、问题集和执行框架一致，仅改变关键模块开关。

四种实验模式定义如下：D_baseline0 为纯 LLM 基线；A_template 在 D 基础上加入知识图谱模板策略；B_data_aware 在 A 基础上加入数据洞察；C_iterative 在 B 基础上加入两轮迭代。对应渐进关系为 D、A、B、C 逐级增强。实验覆盖三个研究问题（技术影响力、技术融合趋势、国家竞争态势），总计 12 组任务。数据集为 `data/new_data.XLSX`，包含 10000 条样本与 22 个字段。

## 5.2 系统性能评估
为减少单一评估口径偏差，本文使用"双轨评估"：结构指标 + 语义评估[19][30]。

第一类为自动化结构指标，共 10 项，直接由实验 JSON 提取。核心指标包括列覆盖率、方法多样性、参数丰富度、任务描述详细度、针对性引用数、预期结论具体度等。该类指标反映“方案结构质量”和“数据耦合程度”。

第二类为 LLM-as-Judge 评估，从相关性、针对性、方法合理性、创新性、深度五维度打分，满分 25 分。评估时对四方案匿名化并并列呈现，降低标签偏置。为避免分数塌缩，评分提示要求维度间保留最小差异度[30]。

指标定义细节如下：列覆盖率用于衡量方案利用数据广度；方法多样性用于衡量任务设计丰富度；针对性引用数衡量方案中引用具体数据证据的密度；参数丰富度反映执行可操作性。上述指标共同指向“是否从模板生成转向证据生成”这一核心判断。

### 5.2.2 结果分析与讨论
#### 5.2.2.1 总体梯度：A < D < B < C
最关键现象是 A 低于 D。若知识模板单独介入，系统可能被过早约束在固定分析框架中，反而失去针对具体数据做灵活规划的能力。B 和 C 的提升说明，知识约束只有与数据证据结合时才具备稳定正增益[24][25]。

#### 5.2.2.2 知识图谱约束悖论
A_template 低于 D_baseline0 对应“知识图谱约束悖论”：结构约束并非天然增益，约束强度与证据强度必须匹配。若证据强度不足，约束会转化为模板化路径依赖，表现为针对性下降和创新性下降。

#### 5.2.2.3 数据洞察的直接贡献
B 相比 A 在针对性引用数大幅提升，且在 LLM 针对性维度提升明显。该结果说明 DataPreview + GraphPreview 并非仅增加上下文长度，而是实质改变了任务设计方向，使任务从“问题语义导向”转向“数据证据导向”。

#### 5.2.2.4 两轮迭代的深度贡献
C 在深度和创新性上达到最高值，且方法多样性和任务数同步增加。该组合特征说明第二轮并非简单重复第一轮，而是围绕第一轮证据缺口进行补充，形成了层级化分析路径。

#### 5.2.2.5 B_data_aware 的结构指标异常分析
值得注意的是，B_data_aware 在列覆盖率（0.258）、方法多样性（2.667）、任务描述详细度（48.600）和生成任务总数（2.667）等结构指标上低于 D_baseline0，但在针对性引用数（7.667 对 2.667）和 LLM 总分（21.67 对 19.67）上显著领先。该现象并非数据感知机制的失效，而是反映了一种"聚焦效应"：数据洞察引导系统从泛化规划转向证据驱动规划，使 Strategist 优先选择数据支持最强的 2-3 个方向深入分析，而非生成更多但缺乏数据支撑的通用任务。换言之，B 模式的结构指标下降是"以广度换深度"的策略结果——任务数更少但每个任务与数据的耦合度更高，这一判断可由针对性引用数的大幅提升佐证。该发现提示，评估数据感知机制时，仅依赖数量型结构指标可能产生误导，需结合语义评估指标综合判断。

#### 5.2.2.6 工程可用性观察
四模式代码执行成功率均为 1.000，说明实验差异主要来自“规划质量差异”，而非执行失败差异。这一结果强化了本文核心命题：在执行稳定条件下，决定上限的是方案设计质量。

### 5.2.3 有效性威胁与缓解
第一，单次实验的可靠性问题。当前每组实验仅运行一次，未进行多次重复和统计显著性检验。该设计的合理性基于以下考量：（1）LLM-as-Judge 评估采用低温度参数（temperature=0.1），输出接近确定性，多次评估的分数波动极小；（2）数据预处理模块（DataPreview、GraphPreview）使用固定随机种子（random_state=42），输出完全确定性；（3）从跨问题一致性角度，三个研究问题均独立呈现 A < D < B < C 的梯度趋势（表 5-4），该一致性本身提供了非正式的"跨样本复验"，降低了单次结果的偶然性风险；（4）各模式间的评分差距较大（如 A 总分 14.33 对 C 总分 24.00，差距达 67.5%），即使存在一定波动也不影响排序结论。但该局限仍需在后续工作中通过多次独立运行和 bootstrap 置信区间检验加以改善。

第二，评估模型偏差风险。LLM-as-Judge 可能存在偏好偏移。本文采用匿名并列评分与低温度参数缓解该问题，但仍建议后续引入人工盲审做交叉验证。

第三，问题集规模限制。当前仅包含三个研究问题，虽覆盖三类典型场景，但统计外推仍有限。后续可扩展问题库并做跨数据集复验。

第四，任务配置依赖。不同模型版本和提示模板可能影响绝对分数。本文通过相对比较和同环境消融控制该影响，但跨版本可比性仍需后续补充。

## 5.3 本章小结
本章通过四方案消融证明：数据感知和两轮迭代是稳定提升的关键机制；知识图谱单独使用并不保证收益，需与数据证据协同。实验结果为本文提出的系统设计提供了直接实证支持，也为后续应用示例章节提供了可解释基础。
