第一章 绪论

1.1 研究背景与意义

专利文献及其结构化元数据是技术创新活动的重要外显载体。与普通科技文本相比，专利数据同时具有"技术属性、法律属性、时间属性、组织属性"四重特征，这使其天然适合用于技术演化分析、竞争态势分析和创新能力评估[1][2][4]。长期以来，专利计量分析在科技政策制定、企业技术战略规划和创新能力评估中发挥着不可替代的作用[3][6]。然而，在实际研究场景中，专利计量分析仍高度依赖人工流程：研究者通常需要手工定义变量、挑选统计方法、设置控制变量并反复调整分析路径。该流程的专业门槛高、耗时长、复现实验成本大，且在面对新问题时迁移效率较低[5][7]。

近年来，大语言模型（Large Language Model, LLM）推动了自动化数据分析系统的快速发展[20][31]。已有工作在任务分解、代码生成、执行纠错等方面取得显著进展，例如 DS-Agent[16]、Data Interpreter[17] 等系统展示了多智能体协作在复杂分析任务中的可行性。多智能体框架如 AutoGen[11]、MetaGPT[12] 等进一步提供了可编程的协作机制，使得构建复杂的端到端分析系统成为可能[10]。但现有系统的优化重点主要集中在"执行层"，即如何更稳定地完成既定分析任务；对于"规划层"，即如何在给定研究问题与具体数据集时自动形成高质量分析方案，现有方法仍不充分[19]。该差距在专利计量场景更为明显，因为专利变量关系复杂、字段语义多样、跨列关联隐含，若缺乏前置数据感知，系统易产生模板化、泛化但不贴合数据事实的方案。

另一方面，知识图谱增强 LLM 已成为热点方向。GraphRAG[24] 等研究表明，图结构能够提升复杂问题的全局信息组织能力。在知识图谱与 LLM 的融合路线上，已有系统性的路线图综述[25]。在专利领域，EvoPat[21]、KLIPA[22] 等工作开始尝试将 LLM 与知识组织或检索能力结合。但总体上，已有研究更多服务于问答、摘要、检索等文本任务；针对"专利结构化数据上的分析方案自动设计"仍缺少系统性方法[23]。由此，本文聚焦"数据感知驱动的多智能体专利分析方案生成"，试图补足从执行自动化到规划自动化的关键环节。

从实践价值看，若能在规划前自动提取数据分布、图结构、样本语义等证据信息，并将其与领域知识约束协同使用，可显著降低人工试错成本，提高研究可复现性与结论可解释性。对专利计量研究者、技术情报分析师和企业知识产权部门而言，这一能力均具有直接应用价值。

1.2 研究问题与研究内容

围绕上述背景，本文的核心研究问题定义为：如何构建一个多智能体系统，使其能够基于具体专利数据集自动生成数据感知的分析方案，并在执行反馈基础上进行迭代优化，从而稳定提升分析质量。

为回答该问题，本文开展三项研究内容：

第一，提出数据感知方案生成机制。系统在正式规划前，先通过 DataPreview 提取列级统计与跨列关系，通过 GraphPreview 提取网络结构特征，并结合分层抽样摘要触发 LLM 生成"可检验洞察"。该机制的目标是把"数据事实"显式注入规划上下文，减少纯语义驱动导致的模板化风险。

第二，设计双知识图谱协同机制。本文将因果图谱用于约束"研究假设空间"，将方法图谱用于约束"分析执行空间"，并在 Strategist 阶段实现二者联动[25][26]。该设计旨在同时保证方案具备理论解释性与方法可执行性。

第三，构建两轮迭代优化机制。第一轮聚焦探索性分析，第二轮基于第一轮结果做差距识别和验证性深化，形成"探索—验证"闭环。该机制用于提升分析深度、机制解释能力和结论稳健性。

1.3 研究方法与技术路线

本文采用"系统构建 + 渐进消融 + 双重评估"的研究方法。

在系统构建层面，本文基于 LangGraph[15] 设计四智能体协作流程：Strategist 负责分析蓝图生成，Methodologist 负责任务技术规格化，CodingAgent 负责代码生成与纠错执行，Reviewer 负责结果校验与报告生成。系统以状态机方式组织任务流，支持结构化输入、过程追踪与结果落盘。

在实验层面，本文采用四方案渐进消融设计：D_baseline0（纯 LLM）、A_template（仅知识图谱模板）、B_data_aware（知识图谱+数据洞察）、C_iterative（数据洞察+两轮迭代）。该设计可分离关键模块贡献，避免"整体提升但原因不明"的评估陷阱。

在评估层面，本文联合两类指标：其一为自动化结构指标（列覆盖率、方法多样性、参数丰富度、任务数等）；其二为 LLM-as-Judge 语义指标（相关性、针对性、方法合理性、创新性、深度），该方法已在 LLM 评估领域得到广泛验证[30]。前者强调可复核的结构质量，后者强调研究问题回答质量，两者互补。

1.4 研究难点与创新点

本文研究存在两个核心难点。

第一，如何让分析方案与数据事实保持高一致性。现实中 LLM 容易输出"表面合理"的泛化路径，但未必对应当前数据集的真实分布与结构特征。若无法把数据证据转化为规划约束，自动化系统将难以超越提示词工程式模板。

第二，如何平衡"知识约束"与"生成自由度"。知识图谱可以提升结构一致性，但过强约束可能抑制有效探索。如何找到约束与开放之间的可操作平衡，是系统设计关键。

针对上述难点，本文形成三点创新：

（1）提出"数据感知前置"的方案生成流程。通过 DataPreview、GraphPreview 与洞察生成模块，将数据证据前移至规划阶段，形成"数据先证据化、方案后生成"的机制。

（2）提出双知识图谱协同架构。将"因果解释"与"方法执行"拆分到两个图谱并在规划阶段联动，提升方案的理论一致性与执行可行性。

（3）发现并解释"知识图谱约束悖论"。实验中观察到 A_template 低于 D_baseline0，说明知识约束并非必然增益；只有与数据感知协同时，图谱约束才能转化为稳定性能提升。

1.5 论文结构安排

全文共七章，各章之间的逻辑关系如下。

第一章说明研究背景、问题定义、研究方法与贡献。
第二章梳理 LLM 自动化分析、多智能体协作框架、LLM 专利应用、知识图谱增强 LLM 的研究进展，并归纳现有不足。
第三章给出系统设计目标、总体架构与应用场景。
第四章描述系统实现细节，包括数据预览、图结构预览、双图谱调用、蓝图生成与两轮迭代。
第五章给出实验设计、评估方法、结果对比与机制分析。
第六章通过完整案例展示系统从输入问题到输出结论的端到端流程。
第七章总结研究结论并讨论未来工作方向。
